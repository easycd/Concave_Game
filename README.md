# 오목

React · TypeScript · Node.js · Socket.IO로 만든 실시간 온라인 오목 게임입니다. 1대1 대전과 2대2 팀 대전, 관전, 채팅을 지원합니다.

**[게임 플레이하기](https://wodnjs.com/omok/)** · [배포 안내](./DEPLOY.md)

개인 서버(wodnjs.com)의 `/omok/` 경로에서 돌아갑니다. 로그인은 wodnjs.com 홈페이지 계정으로 합니다.

## 주요 기능

- **규칙 선택:** 방 생성 시 자유 오목 또는 렌주 규칙을 선택합니다. 렌주에서는 흑의 삼삼·사사·장목 금수 자리에 반투명 X를 표시하고 착수를 차단합니다. 막힌 삼과 금수로만 확장 가능한 삼은 제외합니다.
- **1대1 / 2대2 대전:** 2대2에서는 팀원을 번갈아가며 같은 색 돌을 놓습니다.
- **홈페이지 통합 로그인:** 이 게임에는 자체 가입·로그인이 없습니다. wodnjs.com 홈페이지에서 로그인하면 같은 도메인의 로그인 쿠키(`wj_session`)를 홈페이지 서버에 확인해 그 회원으로 들어옵니다. 로그인하지 않았으면 홈페이지 로그인 창으로 넘어갔다가 돌아옵니다.
- **전적과 랭킹:** 메인 화면에서 내 승·패·무와 승률을 확인합니다. 승리 수를 기준으로 상위 10명의 랭킹을 표시하며 1대1과 2대2 결과를 홈페이지 회원별로 서버에 영구 저장합니다.
- **로비 전체 채팅과 접속자:** 로비에서 모든 대기 이용자와 실시간으로 대화하고, 현재 접속자의 플레이중·대기중 상태와 전적을 확인합니다.
- **로비와 초대:** 방 생성, 6자리 방 코드·초대 링크 복사, 팀 자리 이동, 준비와 시작.
- **관전:** 방마다 최대 3명이 관전하며 채팅에 참여할 수 있습니다. 대국 종료 후에도 빈 플레이어 자리로 이동할 수 있습니다.
- **재대국 신청:** 종료 후 한판더 신청하기 버튼이 나타납니다. 상대 팀이 수락해야 준비 화면으로 이동하며, 모두 준비하면 방장이 흑백을 바꿔 다음 판을 시작합니다.
- **무승부 신청:** 대국 중 신청하면 상대 팀원 한 명이 10초 안에 수락하여 무승부로 종료할 수 있습니다. 거절하거나 시간이 지나면 신청이 취소되며, 응답 중에도 착수 제한 시간은 계속 흐릅니다.
- **시간 설정:** 방 생성 시 매 차례 제한 시간을 2~300초로 설정합니다. 기본값은 30초이며 시간 초과 시 해당 팀이 패배합니다.
- **차례 안내:** 중앙에 현재 플레이어를 표시하고 내 차례에는 바둑판 테두리와 플레이어 카드 왼쪽을 초록색으로 강조합니다.
- **타이머:** 남은 시간과 진행 바를 표시하며 마지막 5초에는 타이머와 바둑판 테두리의 빨간색 애니메이션으로 알립니다. 상단에는 대국 경과 시간을 표시하고 종료 시 멈춥니다.
- **가위바위보:** 팀 대표가 10초 안에 선택합니다. 무승부 안내 후 다시 선택하며 승리 팀·선공·후공을 작은 팝업으로 3초간 표시합니다.
- **실시간 채팅:** 넓은 채팅창을 제공하고 채팅과 착수를 독립적으로 처리합니다. 채팅 전송 간격 제한은 없습니다.
- **승패 안내:** 대국 종료 시 본인 기준 승리·패배를 큰 결과창으로 표시합니다. 승리는 초록색·금색 트로피, 패배는 붉은색으로 구분하며 관전자에게는 승리 팀을 안내합니다. 닫은 결과창은 다시 열 수 있고 상단 승패 표시도 유지됩니다.
- **대국 기록:** 현재 방문 중 완료한 대국의 결과와 착수 순서를 확인하고 다시 볼 수 있습니다.
- **화면 대응:** FHD·QHD 및 모바일 화면에 맞춰 배치하며 모바일에서는 바둑판, 참가자, 채팅을 세로로 표시합니다.
- **방 정리와 재연결:** 마지막 플레이어가 퇴장하면 방을 삭제하고 관전자를 로비로 돌려보냅니다. 연결이 끊긴 참가자는 20초 동안 재연결할 수 있습니다.

## 게임 규칙과 진행

1. wodnjs.com 홈페이지에서 로그인(닉네임 2~12자)한 뒤 `/omok/`로 들어옵니다. 닉네임은 홈페이지 계정 것을 씁니다.
2. 방을 만들거나 방 코드·초대 링크로 참가합니다. 대기 중 빈 자리로 이동할 수 있으며 자리 이동 시 준비 상태가 초기화됩니다.
3. 모든 플레이어가 준비하면 방장이 시작합니다.
4. 각 팀의 첫 번째 플레이어(1번·2번)가 가위바위보를 선택합니다. 둘 다 선택하면 즉시 판정하며 이긴 팀이 흑돌로 선공합니다. 무승부나 양쪽 미선택은 새 10초 라운드로 다시 진행하고, 제한 시간 내 한쪽만 선택하면 선택한 팀이 승리합니다.
5. 2대2에서 **1·3번은 1팀**, **2·4번은 2팀**입니다. 1팀 선공은 **1 → 2 → 3 → 4**, 2팀 선공은 **2 → 1 → 4 → 3** 순서입니다.
6. 자유 오목은 같은 색 돌을 **5개 이상** 연결하면 승리합니다. 렌주에서 흑은 정확히 5개, 백은 5개 이상 연결하면 승리합니다. 흑의 삼삼·사사·장목은 금수이며 정확한 오목이 동시에 완성되면 승리를 우선합니다. 가위바위보로 색을 정하는 기존 방식은 유지하며 대회용 오프닝 교환 규칙은 적용하지 않습니다. [렌주 금수 판정 기준](https://www.renju.net/rifrules/)
7. 시간 초과·기권·대국 중 퇴장은 해당 팀 패배입니다. 연결이 끊겨도 착수 제한 시간은 계속 흐르며 20초 후 퇴장 처리합니다.
8. 대국 종료 후 방장이 **흑백 바꿔 한 판 더**를 누르면 팀의 돌 색깔을 서로 바꿉니다. 모두 준비하고 시작하면 두 번째 판부터는 가위바위보 없이 새 흑돌 팀이 선공합니다. 매 판 흑백이 교대하며, 첫 판의 색이 결정되기 전에 끝난 경우에는 다음 판에도 가위바위보를 진행합니다. 왼쪽 상단의 **오목**을 누르면 메인 페이지로 이동합니다.

## 개발 환경과 실행

Node.js **22~24**와 npm이 필요합니다.

```sh
git clone https://github.com/easycd/Concave_Game.git
cd Concave_Game
npm ci
npm run dev
```

웹 화면은 [http://localhost:5173](http://localhost:5173), 개발 서버는 3001 포트를 사용합니다. 로그인 확인을 위해 홈페이지 서버(`wodnjs.com_Web`, 8080)를 함께 띄워야 합니다. 다른 브라우저나 시크릿 창에서 다른 홈페이지 계정으로 접속하면 참가자를 나누어 테스트할 수 있습니다.

## 빌드와 운영 실행

```sh
npm run build
npm start
```

기본 운영 주소는 [http://localhost:3001](http://localhost:3001)입니다. 환경 변수 `PORT`로 포트를 변경할 수 있습니다. 운영 서버는 빌드된 웹 화면과 Socket.IO 연결을 같은 주소에서 제공합니다. `OMOK_DATA_DIR`이 있으면 전적을 그 폴더의 `records.json`에 저장하고, 없으면 메모리 저장소를 사용합니다.

Docker 실행 설정은 `Dockerfile`에 있습니다. 자세한 절차는 [DEPLOY.md](./DEPLOY.md)를 참고하세요.

## 검증

```sh
npm test
npm run build
npm run test:deployment
```

- 게임 규칙과 가위바위보·시간 초과·자리 이동·관전자 제한을 검증하는 단위 테스트.
- 실제 Socket.IO 클라이언트 8개를 연결해 팀 대전, 채팅, 관전, 재연결을 확인하는 통합 테스트.
- 컴파일된 운영 서버의 웹 파일 제공과 실제 WebSocket 대전을 확인하는 배포 테스트.

8개 동시 접속 검증은 최대 수용 인원을 뜻하지 않습니다. 최대 동시 접속자 수를 측정하는 부하 테스트는 아직 진행하지 않았습니다.

## 데이터 보관과 운영 제한

- 누적 전적과 랭킹은 홈페이지 회원 id별로 `OMOK_DATA_DIR/records.json`에 저장되어 서버 재시작 후에도 유지됩니다. 비밀번호는 이 게임에 없습니다. 한 대국은 고유 ID로 한 번만 반영합니다.
- 1대1에서는 두 참가자, 2대2에서는 자리에 앉아 대국한 네 참가자 모두에게 팀 결과에 따라 승·패·무를 반영합니다. 관전자는 전적에 포함하지 않습니다.
- 방·현재 대국·채팅은 **서버 메모리**에 저장합니다. 서버 재시작이나 재배포 시 초기화됩니다.
- 대국 기록은 **현재 방문 중 브라우저 메모리**에만 보관합니다. 새로고침하거나 사이트를 떠나면 삭제됩니다. 같은 앱 안에서 메인·기록 페이지를 이동하는 동안에는 유지됩니다.
- 로그인은 홈페이지가 관리합니다. 잠깐의 연결 끊김이나 새로고침 후 같은 자리로 복귀할 수 있으며 서버에 해당 방이 남아 있어야 합니다. 홈페이지에서 로그아웃하거나 관리자가 계정을 지우면 60초 안에 실시간 연결이 끊깁니다.
- 현재 대국과 실시간 방 상태는 단일 서버 인스턴스의 메모리를 사용하므로 여러 서버 인스턴스 간에는 공유되지 않습니다.

## 개인 서버에서 경로 아래로 실행 (wodnjs.com/omok)

한 서버에서 `https://도메인/omok/` 처럼 경로 아래로 돌릴 때 쓰는 환경 변수입니다. `BASE_PATH`를 주지 않으면 `/`에서 돕니다.

| 변수 | 예 | 설명 |
| --- | --- | --- |
| `BASE_PATH` | `/omok` | 빌드(`BASE_PATH=/omok npm run build`)와 실행 모두에 같은 값을 줍니다. 화면·API·Socket.IO·쿠키가 이 경로 아래로 갑니다. |
| `HOST` | `127.0.0.1` | 받을 주소. 기본 `0.0.0.0` |
| `OMOK_DATA_DIR` | `/var/lib/webgames/omok` | 전적을 이 폴더의 `records.json`에 저장합니다. 없으면 메모리(재시작 때 사라짐) |
| `HOME_AUTH_URL` | `http://127.0.0.1:8080/api/auth/me` | 로그인 확인용 홈페이지 서버 주소(기본값 그대로면 됨) |
| `INTERNAL_TOKEN` | (긴 무작위 문자열) | 홈페이지 관리자 페이지가 전적 조회·닉네임 변경·삭제를 부를 때 쓰는 비밀값. 홈페이지와 같은 값. 없으면 내부 API 꺼짐 |

내부 API `/omok/internal/users/:id` (GET 전적 · PUT `{nickname}` · DELETE)는 `X-Internal-Token`이 맞고, 터널을 거친 요청(`CF-Connecting-IP`·`X-Forwarded-For`가 있음)이 아닐 때만 열립니다. 아니면 404.
